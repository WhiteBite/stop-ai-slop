- V1-контракт нашего плагина работает на текущем stable: хук `tool.execute.before` диспатчится (`packages/opencode/src/session/tools.ts`), input теперь включает sessionID/callID — плагин читает только `input.tool` и `output.args`, совместим.
- Лоадер (`packages/opencode/src/plugin/index.ts`, `applyPlugin`): сначала `readV1Plugin(mod, spec, "server", "detect")` — объект `mod.default` формы `{ id, server }`; при находке — ранний возврат, legacy-скан именованных экспортов не выполняется (двойной регистрации нет). Для file-плагинов с default-формой обязателен строковый `id` (иначе TypeError "Path plugin must export id"); legacy-путь (именованные экспорты) id не требует.

Стаб-реэкспорт в README теперь `export { default } from ...` (одна строка, даёт плагину стабильный id); старая форма `export { CommentGate } from ...` продолжает работать через legacy-путь.
- Отображаемое имя локального плагина = имя файла стаба (discovery-glob `{plugin,plugins}/*.{ts,js}`, identity — file:// URL; `install.ts`: `pkg.json.name ?? basename`). Поэтому в OpenCode плагин виден как "comment-gate" — по имени стаба из наших же README-инструкций; при желании пользователь может назвать стаб `stop-ai-slop.ts`.
- V2 выпущен (теги v2.0.0…v2.0.18; npm dist-tag `latest` пока 1.18.33). V2-контракт модуля: default-экспорт обязан быть `{ id, setup }` или `{ id, effect }` (packages/core/src/plugin/module.ts), лишние ключи игнорируются; v1-имплементации (функция-экспорт, возвращающая объект хуков) в V2 НЕ выполняются (официальный migration guide).

Прежняя заметка «в V2 нет tool.execute.before» основывалась на устаревшем dev-README и неверна.

- Стаб `export { default } from ...` требует OpenCode >= 1.18.29 (включая 2.x); на более старых 1.x работает только legacy-стаб `export { CommentGate } from ...` (лоадер < 1.18.29 вызывает каждый экспорт как функцию — default-объект там не грузится).

## Известные ограничения детектора (не баги, решения)

- `inlineComment` (`src/profiles.mjs:246`, `inlineMarkerAt` :229): c-family профили (флаг `templates`: cfamily/golang/vue) отслеживают backticks state-машиной `templateMarkerAt` (:198) с вложенностью `${ }` — `//` и `/*` внутри template literal это контент строки, внутри `${}` кавычки и backticks переключаются как обычно, маркер валиден только при пустом стеке; экранированные кавычки пропускаются вместе с следующим символом. Остальные профили сохраняют quote-parity эвристику. Остаточное ограничение: детектор построчный — строка, начинающаяся внутри незакрытого многострочного template literal, не отслеживается без состояния файла.
- Вложенные блоковые комментарии OCaml `(* (* *) *)` закрываются на первой `*)` — построчный классификатор, не парсер.
- `multisetDiff` (`src/detect.mjs:228`): реордеринг строк не считается добавлением — корректная семантика diff-гейта, не терять при «улучшениях».
- `.m` не сканируется (Objective-C vs MATLAB), `.pp` замаплен на pascal (Puppet-комментарии `#` пропустятся) — неоднозначные расширения, решение зафиксировано в README.
- Не сканируются: COBOL, ассемблер (`.asm`/`.s`), `.ahk`, `.ipynb`, серверные шаблоны движков (`.erb`, `.ejs`, `.jsp`, `.cshtml`, `.razor`, `.twig`, `.blade.php`, `.pug`, `.haml`).
- `--staged`/`--diff` не видят неотслеживаемые файлы (ограничение git diff) — задокументировано.
- Write-time плагин OpenCode (`plugin/comment-gate.ts`) читает `.stop-ai-slop.yaml` (решение развёрнуто): `evaluateEdit` (`src/gate.mjs:86`) резолвит корень через `resolveConfigRoot` (:20) из `gitToplevel(dirname(resolve(filePath)))`, НЕ из `process.cwd()` — cwd хоста OpenCode часто другой репозиторий (`opts.root` — явный override; `gitToplevel` — `src/git.mjs:100`). Кэш на процесс: каталог→root и root→конфиг (включая null), обе карты с cap 512 и вытеснением старейшего.
- PreToolUse-хук Claude Code: зависший хук НЕ блокирует вызов (таймаут command-хука 600 с, по докам Claude) — гейт обязан оставаться быстрым, не добавлять в `--pre-tool` сетевые/тяжёлые операции.
- MCP `resultType: "complete"` (`RESULT_TYPE_PROTOCOLS`, `src/mcp.mjs:13`) — только на `tools/call` и только при negotiate 2026-07-28 (поле ввела схема 2026-07-28 как обязательное на базовом `Result`; ранние ревизии его не знают). Схема требует его формально и на остальных результатах (`tools/list`/`initialize`/`ping`), но клиент обязан трактовать отсутствие как `complete` (backward-compat clause той же схемы) — эмитим только на `tools/call`. Live-сессия на newest-схеме пройдена.
- `--pre-tool` apply_patch-ветвь (`extractPatchDeltas`, `src/gate.mjs`): V4A-патч разбирается построчно (заголовки `*** Add/Update File`, `*** Move to`, `*** Delete File`, `+`-строки), не grammar-парсером. Экзотический/битый патч без распознанных `+`-строк даёт пустой added → exit 0 (fail-open, как весь `--pre-tool`). Приемлемо: гейт-помощник, не security-граница. V4A не несёт номеров строк — в этой ветке `:line` остаётся индексом добавленной строки (не якорем).
- `--pre-tool` shape-gating для неизвестных имён инструментов: read-only guard (`PRE_TOOL_READ_ONLY`, `src/pretool.mjs:41`) — substring-совпадение по lowercased имени (`read|view|grep|search|glob|list|ls|bash|shell|exec|run|fetch|web|think|todo|plan`). Инструмент с write-формой payload, но read-only-словом в имени, не гейтится. Осознанно: имена нестабильны (VS Code Copilot, Devin), ложное блокирование чтения хуже пропуска.
- Стек tool-директив (`// @ts-expect-error` над `// eslint-disable-next-line`) считается multi-line-раном — осознанный FP: exemptions под конкретные директивы открывают лазейку «два exempt-комментария = не ран». Встречается редко; легаси — через baseline.

- `commentLines` (`src/profiles.mjs`) ведёт состояние блокового комментария по первым 10 строкам: opener, не закрывшийся внутри окна, проглатывает следующие строки как содержимое комментария. По грамматикам языков эти строки и есть комментарий; ложное срабатывание возможно только на синтаксически битом файле или на opener'е внутри многострочного литерала, начинающегося с маркера. Осознанно: общее ограничение «линейное извлечение, не грамматики».

- detekt-сборка НЕ использует `jvmToolchain`: резолвинг toolchain на GitHub-раннере падал (`Failed to calculate the value of task ':compileTestJava' property 'javaCompiler'`) даже при `JAVA_HOME` = JDK 17 от `setup-java`, а локально mascarovался committed-путём `org.gradle.java.installations.paths=D:/SDKs/Java/...` в `gradle.properties`. Цель 17 задаётся напрямую (`kotlin.compilerOptions.jvmTarget`, `JavaCompile.options.release`), байткод major=61 проверен; `gradle.properties` с машинным путём удалён. Не возвращать `jvmToolchain` без foojay-resolver и без проверки на раннере.

- Сильные changelog-маркеры перехода покрыты только в EN и RU; DE/FR/ES представлены слабыми маркерами (нужна пара в одном comment-run). Однострочная наррация перехода на немецком/французском/испанском не флагается. Осознанно: bench-когорта EN-центрична, поэтому FP/FN на других языках невидимы — добавление требует сабаж-фикстур на каждый язык (бэклог: языковые пакеты).

- Внешних бенчмарков у маркеров перехода нет (ревью prior art 2026-10-01). Четыре инструмента того же класса — windbag `HISTORY_NARRATION` (список фраз по границам слов, один хит = срабатывание, `Severity::Error`, doc-блоки НЕ эксемптит, tree-sitter), aislop `ai-slop/meta-comment` (`BEFORE_AFTER_RES`, warning + score-гейт `failBelow: 70`, JSDoc с тегами эксемптит, veto по WHY-маркерам), hyperframes `check-comment-citations.mjs` (один regex + blankout цитат, error, diff-scoped) и mbrc-plugin `HISTORY` (список подстрок, ломает сборку, фиксированные негативные тесты) — все EN-only и **ни один не детектит форму `the old <noun> <verb>`**. То есть ветка B2 (детектор reduced-relative passive) внешнего прецедента не имеет ни подтверждающего, ни опровергающего: её точность держится только на наших фикстурах, и единственный остаточный FP-класс — ровно тот, которого избегают все четыре. Совпадающие с prior art решения: пинанные негативные фикстуры как способ держать границу (mbrc) и закрытые классы вместо списков ключевых слов (aislop). Вывод для следующих правок: расширять B2 нельзя без собственного корпуса легаси-комментариев, внешняя валидация недоступна.

- Пропуски маркеров перехода (цена точности, не баги): в B2 глагол+предлог — «the old parser skipped over empty lines», «behaved like v1», «kept at most 16 entries» (guard на предлог-последователь отсекает reduced-relative passive вместе с частью наррации); «before this change of the parser, …» (of-guard); B3 без пунктуации, союза или маркера слева — «note we used to cache this»; RU-рефлектив «старое кэширование велось»; условное с `бы` перед глаголом — «правило бы держало». Асимметрия B1: «the config must be reloaded before this change takes effect» флагается, а «until this change is deployed the flag stays off» — нет (`until` исключён как rollout-лексика); расхождение по предлогу осознанное, первый случай borderline-TP — «this change» после мержа теряет референт. Ни одна из форм не ловилась и до 0.11.0, регрессии нет.

## Семантики, которые легко сломать невнимательной правкой

- Baseline v2 (`loadBaseline` `src/baseline.mjs:5`, `fingerprint` :25, `maskBaselined` :37): fp = sha256(rule + "\n" + trimmed-строки находки).slice(0,16); файл = заголовок v2 + пары `rel:line` / `fp:<hash>`. Маскинг **с потреблением**: каждая baselined-вхождение гасит одну находку с тем же fp — вставленный повторно идентичный slop флагается. v1-файлы (только `rel:line`) маскируют по-старому до следующего `--baseline-write`. Не «улучшать» до чистого set-membership: сломается чек «baseline: новый слоп поверх легаси блокирует» (`selftest.mjs:1109`, доказано эмпирически при вводе v2).
- Разделение детектора и baseline: changeset не должен трогать одновременно `src/{markers,detect,rules,profiles,generated}.mjs` (detector-semantics) и `src/baseline.mjs` (baseline-semantics) — иначе регресс маскинга неотличим от намеренного изменения. Механически гейтится `skill/scripts/check-coship.mjs` (списки групп :4-11), escape-hatch `--allow-coship "<причина>"`; CI на PR: `--diff origin/<base>`.
- Generated-детекция (`isGeneratedFile` `src/generated.mjs:6`, `SECURITY_RULES` `src/rules.mjs:246`): slop-правила на сгенерированных файлах эксемптся, security-правила (zero-width/bidi/cjk) — НЕТ (отравленный codegen = supply-chain сигнал). Эксепмт пост-детекционный фильтр во всех режимах, включая `--fix`; write-time гейт внутри репо generated-файл НЕ пропускает целиком: `evaluateEdit` ждёт `keepGenerated`, а `configFindings` (`src/gate.mjs:44`) фильтрует находки до `SECURITY_RULES`; вне репо `addedFromToolArgs` по-прежнему игнорирует generated целиком; `scanGenerated: true` снимает фильтр. Голый `DO NOT EDIT` без слова generat/codegen не эксемптит.
- Weak-pair семантика changelog-marker (`CHANGELOG_STRONG`/`CHANGELOG_WEAK` `src/markers.mjs:3-4`, агрегация weak-ранов `weakRun`/`flushWeakRun` `src/detect.mjs:174-225`): одиночный слабый маркер = проза, флагует пара слабых в одном comment-run ИЛИ один сильный. Не возвращаться к монолитному regex — были ложняки на обычной прозе. Сильные маркеры перехода (0.11.0) отобраны по принципу «референт может быть только диффом» и держатся на guard'ах, снятых по воспроизведённым FP двух независимых проверок, — не ослаблять и не расширять без bench+фикстур: (1) `before|prior to|after|since` + **дейксис `this`** + `change|refactor|rewrite` и lookahead `(?!\s+(?:of|request)\b)` — существительные `commit|update|migration|release|fix|patch` и определители `that|our` исключены осознанно (коммит транзакции, миграция схемы, продуктовый релиз, апстрим-фикс, «patch window»/«fix pack» в ops); (2) `the old X <прошедший глагол>` с закрытым классом предлогов-последователей (`for|by|as|to|with|in|…`) и окном `(?!\s+[\w-]{1,20}\s+by\b)` — это синтаксический детектор reduced-relative passive («kept for backwards compatibility», «assumed non-null by callers»), а не список ключевых слов; `would`/`did`/`former` исключены: модаль и условность неотличимы от домена («the old value would be overwritten by the merge»); (3) `(we|they|it|this) used to` требует слева начала комментария, пунктуации или слова из закрытого списка — иначе purpose-clause («the token we used to authenticate»); в список входит `rem`, потому что маркер комментария batch/VB оканчивается на букву и иначе съедал бы левый контекст (`REM we used to cache this`); (4) `used to … has|have been removed|deleted|replaced|dropped` — ко-маркер снятия, clause-local через `[^,.;\n]{0,50}`; (5) RU-ветки: только дейксис «этого изменения»/«этой правки», голые «фикса»/«коммита»/«рефакторинга» исключены (runbook и транзакция); в B5 явные нерефлективные окончания + `(?![а-яё])` и guard на условное `бы`, а основа — явный список склонений `стар(?:ый|ое|ая|…)`/`прежн(?:ий|ее|яя|…)`, НЕ голая `стар[а-яё]*`: последняя флажила «старший байт держал флаги состояния» и «стартер держал заряд», то есть FP на error-правиле в частотной RU-лексике, где «старший» значит «верхний/высший», а не «прежний». **Ловушка:** `\b` в JS и Java ASCII-ный, вокруг кириллицы он молча ломается — в RU-ветках границей служит `(?![а-яё])`, не `\b`. Важно: `CHANGELOG_STRONG` тестируется построчно против `raw` ВМЕСТЕ с маркером комментария (`src/detect.mjs:135`), поэтому якорь `^` там не срабатывает — только lookbehind. Остаточный FP-класс (принят): «the old <компонент> <активный прошедший глагол> <объект>» про легаси-путь, который всё ещё жив в дереве («the old parser assumed latin-1 input») — статически неотличим от наррации; выход: suppression-директива, `rules: changelog-marker: warning` в конфиге или baseline.
- obvious-comment (`OBVIOUS_WHY`/`OBVIOUS_STOPWORDS` `src/markers.mjs:39,34`, матчинг `isObviousComment` :55): иммунитет «почему»-маркеров (intentionally, deliberately, only, UTC, единицы, т.к., должен…) и CJK-гард выточены по FP с bench-когорты (PowerShell `.editorconfig` «indent_size intentionally not specified»); запятая в комментарии требует 2 совпадений слов с кодом, без запятой — 1.
